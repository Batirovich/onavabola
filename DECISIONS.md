# Decisions log

Autonomous decisions made while building, with brief rationale. Newest at the bottom.

- **React 19 / Vite 8 / TS ~6.0 (whatever `create vite@latest` scaffolded today)** instead of pinning older majors — no reason to fight the toolchain's current defaults for a greenfield demo.
- **Tailwind v4 (CSS-first `@theme`, `@tailwindcss/vite` plugin)** instead of v3 + `tailwind.config.js` — the brief wants a fully custom token palette with no default Tailwind colors in the UI; v4's `@theme` block is the more direct way to define that and avoids shipping the default color ramp at all.
- **Fonts: Alegreya (display) + Source Sans 3 (text)**, chosen after programmatically checking ~25 Google Fonts candidates for the U+02BB glyph (see `DESIGN.md`). Popular first choices (Fraunces, Newsreader, Inter, Roboto, Rubik, Karla) do not ship that codepoint at all and were rejected before any UI work.
- **React Router in `BrowserMode` (createBrowserRouter)** with a `_redirects`/`vercel.json` rewrite for static hosting, rather than hash routing — cleaner URLs (`/monitor`, `/community`) for a jury demo, and both Netlify and Vercel support SPA rewrites trivially.
- **Project folder name:** `Ona va Bola` on the Desktop (as the user requested), package name `ona-va-bola` inside `package.json`.
- **Fonts self-hosted, not linked from Google Fonts CDN.** The exhibition venue's wifi is an unknown, and a jury demo cannot depend on it — 4 variable-font woff2 files (~145KB total) are checked into `src/assets/fonts`. The `latin` subset already contains U+02BB for both families, confirmed by fetching the real Google Fonts CSS and reading the `unicode-range`.
- **Monitor "learning day" is a separate narrative counter from the 28-day historical dataset.** The confidence-over-time *chart* uses the full 28-day series (days 1–21 rising 45%→80%, days 22–28 plateaued) so the stats pages have a believable longer history. The live "Day 14 of 21" state shown on first load of `/monitor` (matching the brief's own example copy) is a fixed demo starting point independent of that chart, specifically so the "Fast-forward 21 days" simulate control has something dramatic to do on stage — it animates the counter from day 14 to day 21 rather than replaying already-known history.
- **Clinic mothers/children (60 + 25) and community posts/replies (30 + 77) are seeded-random, not hand-written line by line**, aside from ~30 hand-authored community posts (content quality matters there since the jury will read them). Tabular clinic data is generated from name pools + weighted distributions via the shared `createRng` — deterministic, but not worth hand-authoring 85 records.
- **`predictReasons()` uses distinct baseline priors per cry reason (hunger highest, discomfort lowest), not equal weights.** First pass gave every reason ~1.0 baseline, so a "neutral" context (no single strong trigger — the common case) produced a flat ~17%-each spread across all six reasons. That reads as "the model doesn't know," which undercuts the flagship demo. Realistic base rates plus a slightly higher confidence exponent now produce a clear leader (~30-60%) even without a dominant contextual trigger, matching the brief's own example ("Hunger 62%, Wants to be held 21%, Pain/gas 9%…"). Caught by actually clicking "Simulate cry" in a real browser rather than trusting the types.
- **One phone app, three demo personas.** The brief lists Pregnancy, Baby, and Speech as tabs of the same `/app`, but no single mother is simultaneously pregnant, has a 3-month-old, and has a 3-year-old in speech therapy. Home/Recovery/Baby/Profile stay on the primary persona (Malika + Aziz); the Pregnancy tab previews a clearly-labeled second demo profile (Nilufar, week 24, with a 1–40 week slider — "switchable" per the brief); the Speech tab previews a third (Dilnoza + Madina, age 3). Each cross-profile tab has a small banner explaining it's a different demo account, so it reads as an intentional "preview the whole product" choice rather than a data bug.
- **`Intl.DateTimeFormat('uz', ...)` is not used for month/weekday names — they're hand-written arrays instead** (`src/lib/format.ts`). Node and full-ICU browsers render `uz-Latn` correctly ("28-sentabr"), but the Playwright-downloaded Chromium headless-shell build (minimal ICU) silently fell back to a garbled "M09 28, Mon" during verification. A real installed Chrome/Firefox/Safari almost certainly has full ICU, but the exhibition laptop's exact browser build isn't something to gamble on for a jury demo, so the safer, verified-correct path won out over relying on Intl's uz coverage.
- **The site's light/dark toggle governs the marketing chrome (header, footer, landing) only — the "device surface" pages keep a fixed theme of their own**, the same way `/monitor` is deliberately always night-mode. The phone-app screens (`/app`), the clinic dashboard, and the community feed render as a fixed light "paper" surface regardless of the site theme, because they're simulating a specific product UI rather than a marketing page — verified in a dark-mode screenshot pass and it reads intentionally (a lit phone screen / printed dashboard against a dark page), not as a contrast or legibility bug. Retrofitting every card in those three areas to theme-aware tokens was judged not worth the risk this late in the build versus the payoff, given nothing is actually illegible.
- **DemoBadge moved from a `fixed` floating overlay into the sticky header** (desktop: inline next to the language switch; mobile: inside the hamburger menu panel; `/monitor`: in its own header, hidden below `sm` to avoid crowding). A floating badge pinned to the viewport corner inevitably drifts over real content somewhere on a tall page — caught during the responsive pass sitting directly on top of the phone app's tab bar and, before that fix, over the hero's mute button. Docking it in the already-sticky header keeps it "persistent" per the brief without the collision risk.
- **Post-launch design revision round, driven by direct user feedback** ("icons feel generic/default," "the app section doesn't feel like a real mobile app," wants a better device showcase):
  - Rebuilt `DeviceIllustration.tsx` from a flat rounded-rect into a layered product render (volumetric body gradient, glossy cap sheen, dot-matrix speaker grille, glow-bloom light ring, trailing power cable, a small tile-motif brand stamp) — still pure SVG, no image-generation tool was available to produce an actual photo/render.
  - Added `src/components/icons/BrandIcons.tsx`: a small hand-drawn icon set (pregnancy, recovery, monitor, speech, community, the 6 app tab icons, and the 4 monitor simulate-control icons) replacing generic lucide-react defaults and the landing pillars' emoji, specifically in the highest-visibility "feature icon" spots. Left lucide icons in place for functional/status UI (wifi, temperature, close buttons, chevrons) — bespoke icons matter for brand feature moments, not for a device status bar where standard iconography is actually more legible.
  - Reworked `/app` for a native-app feel per explicit direction: `Card` got a bigger radius and softer layered shadow, added `ListRow`/`ListGroup` (iOS-style grouped rows with dividers, replacing individually-boxed list items) for reminders/vaccinations, all primary CTAs became full-width/bold/rounded-2xl with a subtle press-scale, and `EpdsFlow` became a real bottom sheet (spring slide-up, rounded top, drag handle, dimmed backdrop) instead of an instant full-panel takeover.
- **Full audit pass, prompted by "check for coding errors / is this presentable."** Found and fixed real issues rather than just reassuring:
  - Three date/data-consistency bugs from calling the browser's real clock instead of the app's fixed demo anchor (`TODAY` = 2026-09-28, everything else in the dataset is generated relative to it): `HomeTab`'s greeting date and "next checkup" date now use `TODAY`; `useMonitorDemo`'s live cry simulation now combines the real time-of-day (so it still feels "live" during a demo) with the fixed `TODAY` date, otherwise `lastFeedForNow()` would compare against feed events generated for a different day and produce a nonsense "last fed N thousand minutes ago" once run on any date other than the exact day this was built.
  - `DoctorReport`'s table literally rendered today's formatted date as a column header instead of a "Date" label — leftover from early scaffolding, never caught because it happened to still look like a plausible header at a glance.
  - A real layout regression from the icon-set change: 6 tabs with fixed-width `w-12` icon pills didn't fit the 300px phone frame, clipping "Profil" off the edge entirely. Fixed with a tighter icon circle, `min-w-0` + `break-words` on labels so long Uzbek words (`Homiladorlik`) can wrap instead of forcing overflow.
  - `/app` on desktop was a single small phone mockup centered in a mostly-empty page — reads as unfinished on a wide screen. `AppShell` now supports optional external control (`activeTab`/`onTabChange`), and `MotherApp` adds a clickable feature list beside the phone that drives it live — fills the space with real content instead of decoration.
  - Community's moderation log (the AI-safety demo feature) was stacked below all 30 posts, invisible without scrolling past the entire feed, and the page only used the center third of a wide screen. Now a sticky right-rail alongside a wider feed column — visible immediately, no scrolling required.
- **Fixed a genuine grid bug in `PillarsSection`, flagged by the user as an awkward empty gap next to the monitor card.** The flagship monitor tile was declared `lg:col-start-2` with no `lg:col-span`, so on the `grid-cols-4` layout it only ever occupied column 2 — column 3 sat empty beside it, which is exactly the dead space visible in the screenshot. Added `lg:col-span-2` so the card actually spans columns 2–3 as originally intended, and reflowed its internal content to a horizontal device+copy layout now that it has the width to support one.
- **Replaced the hand-coded SVG device illustration with the user's own generated product artwork.** The user created three marketing renders externally (device spec sheet, angle/color variants, an atmospheric night scene) and dropped the source PNGs into `src/assets/`. Two derived assets were extracted and committed:
  - `device-hero.png/webp` — the clean front-view device render, alpha-matted out of its white card background. First pass used a naive color threshold + `ImageFilter.MinFilter` erosion for defringing, which silently collapsed the alpha channel to pure binary (0/255) and produced visibly jagged/pixelated edges — caught by zooming into the actual pixels rather than trusting the small preview. Redone properly: a flood-fill from the image border (using a generous "near-white" connectivity threshold) determines which pixels are truly background-connected, then alpha is set as a *smooth* ramp based on color-distance-from-white within that region (not a hard cutoff), and edge colors are decontaminated (un-blended from the assumed white backdrop) — this preserves anti-aliased edges and leaves enclosed white highlights on the device body untouched. `DeviceIllustration.tsx` now renders this image with a CSS-only glow + pulsing-ring overlay positioned at the light ring's actual pixel location in the source art (measured, not guessed), so the existing `state` prop (idle/listening/crying) still animates. Used on the landing hero, the flagship pillar card, and the monitor page's live-view panel — replacing the SVG everywhere it appeared.
  - `monitor-device-scene.png/webp` — a tighter crop of the same source's "night" composition (device + glow + nightstand, crib and all baked-in text excluded) used as a proper two-column hero image on `/monitor`. First attempt tried to force this into a short panoramic `background-size: cover` band using a guessed `background-position` (`30%`) — the image's real content spans nearly its full height, so at that band's aspect ratio `cover` cropped out the device entirely, leaving mostly empty dark background. Rather than fight the aspect-ratio mismatch with more CSS tuning, replaced it with a plain two-column layout (text left, image at its own height right) so nothing gets force-cropped.
  - The other baked-in-text images (the annotated parts diagram, the 3-angle/3-color sheet) were deliberately **not** used directly — their labels are hardcoded Uzbek pixels, which would violate the bilingual requirement for any English-locale visitor. Kept as unreferenced source files in `src/assets` (Vite only bundles imported assets, so they add zero weight to the shipped build) in case similar crops are useful later.
- **Post-redesign user feedback: `/monitor`'s hero-band image looked "stuck," and the footer's demo disclaimer was cut down.** Investigated the image complaint rather than guessing — `monitor-device-scene.webp` is an RGB image with no alpha channel (a baked-in dark rectangle), and its corner colors `(31,37,53)`/`(15,25,47)`/etc. don't match the page's `bg-night-900` (`#060a17`), so the image's rectangular bounds were faintly but definitely visible against the surrounding dark background — a real visual bug, not a subjective preference. Rather than re-matting this second, separate source image the way `device-hero.png` was fixed earlier, replaced it outright with the same `DeviceIllustration` component already used everywhere else in the redesigned site (hero, night scene, the monitor's own live-view panel) — it's a proper transparent cutout with a CSS glow, so it blends into any dark background with no edge artifact, and it means `/monitor`'s hero band is now visually consistent with the rest of the site rather than being the one place still using a separate flat photo. Deleted `monitor-device-scene.png`/`.webp`, confirmed via grep they had no other references. Also removed the "All data is fictional and does not belong to real users" sentence from `footer.demoNotice` in both locales per explicit request — kept "This is a demo built for the InnoWeek.Uz–2026 exhibition," since that context is still useful and wasn't the sentence flagged.
- **Reworked the `/jury` team section, per explicit feedback that "Your name here" reads as broken, not honest.** No real team is being announced, but the previous cards (`GeometricAvatar` + bold "Ismingiz shu yerda" / "Your name here" + a dashed "empty slot" border) looked like an unfinished template rather than an intentional choice — exactly the wrong impression for a jury-facing page. Reframed each card around what that role *contributes* instead of a name that isn't there: `TeamMember.placeholder` became `TeamMember.contribution` (e.g. the pediatrician advisor "reviews the cry-reason categories and safety messaging," the nutritionist advisor "prepares Uzbek-cuisine-based recovery nutrition guidance" — each tied to a real feature already in the app, not generic filler), the dashed border became the same solid card style used elsewhere on `/jury`, and the avatar became a role-appropriate lucide icon in the same colored-square pattern `BusinessModelSection` already uses. The section's own subtitle ("the full team is still forming") still does the job of setting expectations; the cards no longer contradict it by pretending there are named slots waiting to be filled.
