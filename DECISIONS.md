# Decisions log

Autonomous decisions made while building, with brief rationale. Newest at the bottom.

- **React 19 / Vite 8 / TS ~6.0 (whatever `create vite@latest` scaffolded today)** instead of pinning older majors — no reason to fight the toolchain's current defaults for a greenfield demo.
- **Tailwind v4 (CSS-first `@theme`, `@tailwindcss/vite` plugin)** instead of v3 + `tailwind.config.js` — the brief wants a fully custom token palette with no default Tailwind colors in the UI; v4's `@theme` block is the more direct way to define that and avoids shipping the default color ramp at all.
- **Fonts: Alegreya (display) + Source Sans 3 (text)**, chosen after programmatically checking ~25 Google Fonts candidates for the U+02BB glyph (see `DESIGN.md`). Popular first choices (Fraunces, Newsreader, Inter, Roboto, Rubik, Karla) do not ship that codepoint at all and were rejected before any UI work.
- **React Router in `BrowserMode` (createBrowserRouter)** with a `_redirects`/`vercel.json` rewrite for static hosting, rather than hash routing — cleaner URLs (`/monitor`, `/community`) for a jury demo, and both Netlify and Vercel support SPA rewrites trivially.
- **Project folder name:** `Ona va Bola` on the Desktop (as the user requested), package name `ona-va-bola` inside `package.json`.
- **Fonts self-hosted, not linked from Google Fonts CDN.** The exhibition venue's wifi is an unknown, and a jury demo cannot depend on it — 4 variable-font woff2 files (~145KB total) are checked into `src/assets/fonts`. The `latin` subset already contains U+02BB for both families, confirmed by fetching the real Google Fonts CSS and reading the `unicode-range`.
- **Monitor "learning day" is a separate narrative counter from the 28-day historical dataset.** The confidence-over-time *chart* uses the full 28-day series (days 1–21 rising 45%→80%, days 22–28 plateaued) so the stats pages have a believable longer history. The live "Day 14 of 21" state shown on first load of `/monitor` (matching the brief's own example copy) is a fixed demo starting point independent of that chart, specifically so the "Fast-forward 21 days" simulate control has something dramatic to do on stage — it animates the counter from day 14 to day 21 rather than replaying already-known history.
- **Clinic mothers/children (60 + 25) and community posts/replies (30 + 77) are seeded-random, not hand-written line by line**, aside from ~30 hand-authored community posts (content quality matters there since the jury will read them). Tabular clinic data is generated from name pools + weighted distributions via the shared `createRng` — deterministic, but not worth hand-authoring 85 records.
- **`predictReasons()` uses distinct baseline priors per cry reason (hunger highest, discomfort lowest), not equal weights.** First pass gave every reason ~1.0 baseline, so a "neutral" context (no single strong trigger — the common case) produced a flat ~17%-each spread across all six reasons. That reads as "the model doesn't know," which undercuts the flagship demo. Realistic base rates plus a slightly higher confidence exponent now produce a clear leader (~30-60%) even without a dominant contextual trigger, matching the brief's own example ("Hunger 62%, Wants to be held 21%, Pain/gas 9%…"). Caught by actually clicking "Simulate cry" in a real browser rather than trusting the types.
- **One phone app, three demo personas.** The brief lists Pregnancy, Baby, and Speech as tabs of the same `/app`, but no single mother is simultaneously pregnant, has a 3-month-old, and has a 3-year-old in speech therapy. Home/Recovery/Baby/Profile stay on the primary persona (Malika + Aziz); the Pregnancy tab previews a clearly-labeled second demo profile (Nilufar, week 24, with a 1–40 week slider — "switchable" per the brief); the Speech tab previews a third (Dilnoza + Madina, age 3). Each cross-profile tab has a small banner explaining it's a different demo account, so it reads as an intentional "preview the whole product" choice rather than a data bug.
- **`Intl.DateTimeFormat('uz', ...)` is not used for month/weekday names — they're hand-written arrays instead** (`src/lib/format.ts`). Node and full-ICU browsers render `uz-Latn` correctly ("28-sentabr"), but the Playwright-downloaded Chromium headless-shell build (minimal ICU) silently fell back to a garbled "M09 28, Mon" during verification. A real installed Chrome/Firefox/Safari almost certainly has full ICU, but the exhibition laptop's exact browser build isn't something to gamble on for a jury demo, so the safer, verified-correct path won out over relying on Intl's uz coverage.
- **The site's light/dark toggle governs the marketing chrome (header, footer, landing) only — the "device surface" pages keep a fixed theme of their own**, the same way `/monitor` is deliberately always night-mode. The phone-app screens (`/app`), the clinic dashboard, and the community feed render as a fixed light "paper" surface regardless of the site theme, because they're simulating a specific product UI rather than a marketing page — verified in a dark-mode screenshot pass and it reads intentionally (a lit phone screen / printed dashboard against a dark page), not as a contrast or legibility bug. Retrofitting every card in those three areas to theme-aware tokens was judged not worth the risk this late in the build versus the payoff, given nothing is actually illegible.
- **DemoBadge moved from a `fixed` floating overlay into the sticky header** (desktop: inline next to the language switch; mobile: inside the hamburger menu panel; `/monitor`: in its own header, hidden below `sm` to avoid crowding). A floating badge pinned to the viewport corner inevitably drifts over real content somewhere on a tall page — caught during the responsive pass sitting directly on top of the phone app's tab bar and, before that fix, over the hero's mute button. Docking it in the already-sticky header keeps it "persistent" per the brief without the collision risk.
- **Post-launch design revision round, driven by direct user feedback** ("icons feel generic/default," "the app section doesn't feel like a real mobile app," wants a better device showcase):
  - Rebuilt `DeviceIllustration.tsx` from a flat rounded-rect into a layered product render (volumetric body gradient, glossy cap sheen, dot-matrix speaker grille, glow-bloom light ring, trailing power cable, a small tile-motif brand stamp) — still pure SVG, no image-generation tool was available to produce an actual photo/render.
  - Added `src/components/icons/BrandIcons.tsx`: a small hand-drawn icon set (pregnancy, recovery, monitor, speech, community, the 6 app tab icons, and the 4 monitor simulate-control icons) replacing generic lucide-react defaults and the landing pillars' emoji, specifically in the highest-visibility "feature icon" spots. Left lucide icons in place for functional/status UI (wifi, temperature, close buttons, chevrons) — bespoke icons matter for brand feature moments, not for a device status bar where standard iconography is actually more legible.
  - Reworked `/app` for a native-app feel per explicit direction: `Card` got a bigger radius and softer layered shadow, added `ListRow`/`ListGroup` (iOS-style grouped rows with dividers, replacing individually-boxed list items) for reminders/vaccinations, all primary CTAs became full-width/bold/rounded-2xl with a subtle press-scale, and `EpdsFlow` became a real bottom sheet (spring slide-up, rounded top, drag handle, dimmed backdrop) instead of an instant full-panel takeover.
